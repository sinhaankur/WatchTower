# Desktop-bundle dependency set — what ships INSIDE the packaged Mac/Linux/
# Windows app (built by scripts/build-python-bundle.sh into
# desktop/python-bundle/python).
#
# This is deliberately LEANER than requirements.txt. The desktop app is the
# personal-appliance flow: it runs the API in-process, uses FastAPI
# BackgroundTasks (NOT a Redis/RQ worker), and deploys locally / over plain
# ssh+rsync (NOT the legacy fabric JSON-file path). So redis, rq, and fabric
# are ~7 MB of code the packaged app can never reach — every install and
# every two-stage-updater payload carried them for nothing. They're omitted
# here.
#
# What STAYS vs requirements.txt:
#   - everything the API needs at startup (core + DB + crypto + rate limit),
#     because the packaged backend crashes if any startup dep is missing
#     (this file is the bundle's ONLY dep source — the v1.20.0
#     python-multipart gap is why every needed dep must be listed here);
#   - openai, because the AI agent + self-heal is a headline desktop feature
#     and only the openai SDK path is wired (self_heal.py / api/agent.py).
#
# What's DROPPED (present in requirements.txt for dev/CI/Docker, which DO run
# the worker + SSH deploys):
#   - fabric   (SSH/rsync legacy deploy path — desktop deploys locally)
#   - redis+rq (durable queue — desktop uses in-process BackgroundTasks)
#
# Keep this in lockstep with requirements.txt for the shared lines; only the
# three optional-extra lines differ. CI's preflight loads watchtower.api:app
# from the bundle, which catches a missing STARTUP dep — but NOT a missing
# lazy dep, so think before dropping anything a feature imports on use.

# Crypto / secret storage — Fernet encryption of env vars, GitHub PATs, SSH
# keys, and the auto-generated secret.key. A STARTUP dep: the packaged backend
# cannot boot without it. Must be listed explicitly — it was previously pulled
# in transitively, and a dep-graph change (the python-minor-patch bump) dropped
# that path, so the bundle shipped without it. Preflight caught the first-launch
# crash before it reached users.
#
# Floor only — NO upper cap and NO env markers, on purpose. The cross-arch
# bundle builder (scripts/build-python-bundle.sh) installs with
# `pip --platform <arch> --only-binary=:all:`, which picks the newest WHEEL
# available per target platform. PEP 508 markers like
# `platform_machine == "x86_64"` do NOT work here — pip evaluates them against
# the HOST (e.g. an arm64 macOS runner cross-building the x64 bundle), not the
# target, so a marker-based split picks the wrong branch and the build dies with
# "No matching distribution for cryptography>=50.0.2". (That was the 2.1.1/2.1.2
# darwin-x64 failure.)
#
# A plain floor lets wheel availability do the right thing automatically:
#   - linux x64/arm64, Apple-Silicon mac, windows → newest wheel = 50.0.2 (fully
#     patched, incl. CVE-2026-69249)
#   - Intel Mac (x86_64) → upstream dropped x86_64 wheels after 48.0.1, so pip
#     resolves to 48.0.1 there. That one arch carries the >=49 cert-chain DoS
#     (availability-only) until upstream restores Intel wheels or we drop the
#     darwin-x64 target.
cryptography>=48.0.0

# Rate limiting
slowapi>=0.1.9

# [agent] LLM agent + self-heal — talks to ANY OpenAI-compatible endpoint.
# Kept in the desktop bundle because AI self-heal is a headline feature.
openai>=1.50.0
